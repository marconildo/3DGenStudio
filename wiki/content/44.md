# Server Deployment

3D Gen Studio can run as a **shared server** so a whole team works on the same projects and assets. The server holds projects, assets, workflow definitions and user accounts — nothing else. ComfyUI, the mesh and motion tools, and every third-party API key stay on each user's own machine.

That split is what makes the server cheap to host: it needs **no GPU** and very little CPU. It is the same `server.js` you already run locally, started with the environment variable `GENSTUDIO_MODE=server`.

There are two ways to install it, both covered below:

- **Synology NAS**, using Docker.
- **Windows Server**, using Node.js directly, with no Docker.

## What runs where

| | Shared server | Each user's machine |
| --- | --- | --- |
| Projects, cards, graphs, boards | ✅ | |
| Assets — images, meshes, thumbnails, motions | ✅ | |
| Workflow **definitions** | ✅ | |
| User accounts and roles | ✅ | |
| ComfyUI, and every workflow **run** | | ✅ |
| Mesh, rig and motion services | | ✅ |
| API keys (Tripo, Hitem3D, Tencent…) | | ✅ |

A generated asset is produced on the user's own GPU and then uploaded to the server, so a teammate sees it as soon as the run finishes. If the server is unreachable when a run completes, the result is spooled to disk and retried — a long generation is never lost to a server blip.

## Before you start

### The two required secrets

The server refuses to start if either of these is wrong, rather than coming up half-configured. That is deliberate and much easier to diagnose than the alternative.

| Variable | Rule | Why |
| --- | --- | --- |
| `GENSTUDIO_JWT_SECRET` | At least 16 characters | Sessions are validated against it. **Keep it** — changing it signs every user out. A per-restart secret would do that on every deploy, so the server will not invent one for you. |
| `GENSTUDIO_ADMIN_PASSWORD` | At least 8 characters | Creates the first administrator, once, while the user table is still empty. If it cannot create that account the server exits — the alternative was a healthy server with no login on it. |

Generate the secret anywhere Node is installed:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

### The rest

| Variable | Default | Notes |
| --- | --- | --- |
| `GENSTUDIO_MODE` | `local` | Must be `server`. |
| `GENSTUDIO_ADMIN_LOGIN` | `admin` | The first administrator's login. |
| `PORT` | `3001` | The server binds all interfaces. |
| `TRUST_PROXY_HEADERS` | on | Set to `0` whenever the server is reachable directly — see the warning below. |
| `PUBLIC_BASE_URL` | — | Only behind a reverse proxy, e.g. `https://studio.example.com`. |

> **Set `TRUST_PROXY_HEADERS=0` on a directly-reachable server.**
> `X-Forwarded-*` headers are trusted by default, and the resulting host goes into every asset URL the API hands out. Left on, a client can send `X-Forwarded-Host: evil.example.com` and the API will answer other users with `https://evil.example.com/assets/…`.
> Behind a proxy, set `PUBLIC_BASE_URL` instead and leave this at `0`: `PUBLIC_BASE_URL` is read *before* the headers, so nothing can spoof it.

### Where the data lives

Everything worth backing up is in **`data/`** — `app.db` plus every image, mesh, thumbnail and motion clip. The path is derived from the process working directory, so it is always `<working directory>/data`. Nothing else on disk holds state.

## Install on a Synology NAS (Docker)

A NAS is a good host for this: the server is I/O-bound rather than compute-bound, and the data sits on the array you already back up.

### 1. Check the NAS can run it

You need **DSM 7.2 or newer** for Container Manager and its Projects interface. On DSM 7.0–7.1 the older Docker package works, but you drive Compose over SSH instead of through the interface.

Then check the CPU architecture, because it decides how you build. Enable SSH (**Control Panel → Terminal & SNMP**), connect, and run:

```sh
uname -m
```

- `x86_64` — the common Intel/AMD models. Build normally.
- `aarch64` — 64-bit ARM. Build for ARM, see step 2.
- Anything else (`armv7l`, `armv5tel`) — the Node base image has no build for it. Use the Windows guide on another machine instead.

### 2. Build the image on your PC

The build runs `npm ci`, a Vite bundle and a from-source compile of SQLite. That is slow on NAS hardware and can run out of memory — and the NAS does not have the repository anyway. Build where the code is.

If `uname` said `x86_64`, from the repository root:

```sh
docker compose build
docker save 3dgenstudio-server:latest -o genstudio-server.tar
```

If it said `aarch64`:

```sh
docker buildx build --platform linux/arm64 -t 3dgenstudio-server:latest --load .
docker save 3dgenstudio-server:latest -o genstudio-server.tar
```

Cross-building runs the compile step under emulation, so expect the ARM build to take several times longer than a native one. Docker Desktop ships everything it needs.

### 3. Load the image onto the NAS

Copy `genstudio-server.tar` to the NAS with File Station — `/volume1/docker/` is a sensible place. Then either use **Container Manager → Image → Add → Add from file**, or over SSH:

```sh
sudo docker load -i /volume1/docker/genstudio-server.tar
```

### 4. Create the data folder and hand it to uid 1000

This is the step that costs people an evening. The container runs unprivileged as the `node` user, **uid 1000**. A folder created through DSM belongs to `root`, so the server cannot create its database and the container sits in a restart loop.

```sh
sudo mkdir -p /volume1/docker/genstudio/data
sudo chown -R 1000:1000 /volume1/docker/genstudio
```

If SSH is not an option, use a Docker-managed **named volume** instead of a bind mount — the image already sets the ownership inside it, so there is nothing to fix. The cost is that the files are then invisible to File Station and Hyper Backup cannot reach them directly. On a NAS, the bind mount is usually worth the one `chown`.

### 5. Create the project

**Container Manager → Project → Create.** Set the path to `/volume1/docker/genstudio`, choose *Create docker-compose.yml*, and paste this:

```yaml
services:
  genstudio-server:
    image: 3dgenstudio-server:latest
    container_name: genstudio-server
    restart: unless-stopped
    ports:
      - "3001:3001"
    environment:
      GENSTUDIO_MODE: server
      GENSTUDIO_JWT_SECRET: "<the 64 hex characters from Before you start>"
      GENSTUDIO_ADMIN_LOGIN: admin
      GENSTUDIO_ADMIN_PASSWORD: "<at least 8 characters>"
      TRUST_PROXY_HEADERS: "0"
    volumes:
      - /volume1/docker/genstudio/data:/app/data
```

> **Do not reuse the repository's `docker-compose.yml` here.**
> That file reads its secrets from a `.env` beside it, via `${GENSTUDIO_JWT_SECRET}`. On a normal Docker CLI a missing value makes Compose refuse to start and say so; **Container Manager substitutes an empty string instead**. The container then starts and dies on the app's own check with `GENSTUDIO_JWT_SECRET must be set to at least 16 characters` — which reads like a bad secret rather than a missing one.
> The tell: `GENSTUDIO_MODE` is a literal in that file and arrives fine, while every `${…}` value is blank. Keep the values inline, as above.

> **Environment changes need a rebuild, not a restart.**
> Whenever you edit those variables, use **Project → Action → Build**. Stop/Start reuses the existing container with its original environment, so a correct fix will look like it did nothing.

### 6. Verify

From any machine on the network:

```sh
curl http://NAS-IP:3001/api/health
{"ok":true,"mode":"server","version":"3.0.0"}
```

Then open `http://NAS-IP:3001` in a browser. You should get the sign-in screen. If the page is blank, see **Troubleshooting** at the end of this page.

### 7. Firewall and HTTPS

**Control Panel → Security → Firewall**: allow TCP 3001 for your LAN. If the NAS firewall is off entirely, there is nothing to do.

For HTTPS, use the DSM reverse proxy — **Control Panel → Login Portal → Advanced → Reverse Proxy**. Point `https://studio.example.com:443` at `localhost:3001`, and add one line to the compose file:

```yaml
      PUBLIC_BASE_URL: "https://studio.example.com"
```

The app pushes changes to open clients over a Server-Sent Events stream at `/api/events`. Response buffering in a proxy delays that stream without breaking anything else, so *"everything works but other people's changes appear late"* points here first.

## Install on Windows Server (Node.js)

No Docker and no container runtime — Node runs `server.js` directly and a service wrapper keeps it alive across reboots. SQLite ships a prebuilt Windows binary, so no compiler is involved.

### 1. Install Node.js

Get the Node **24.x** x64 MSI from [nodejs.org](https://nodejs.org) — the same major version the Docker image uses. Confirm it, and that npm came along at version 11:

```sh
node -v   # v24.x
npm -v    # 11.x
```

### 2. Copy only what runs

Do not clone the repository onto the server. With `comfyui/` and `thirdparty/` it is tens of gigabytes, none of which the server touches.

On your development machine, build the frontend:

```sh
npm run build
```

Then copy exactly this set into `C:\GenStudioServer\`:

```
package.json          server.js         gateway.js       mcp\
package-lock.json     storage.js        dataStore.js     wiki\
version.json          wikiStorage.js    uploadQueue.js   dist\
                      auth.js           logs.js
                      serverMode.js     meshPivot.js
```

This is the same set the Docker image ships. `node tools/check-packaged-modules.mjs` is what keeps that list honest — run it if you ever add a backend module.

### 3. Install the production dependencies

```sh
cd C:\GenStudioServer
npm ci --omit=dev
```

About 625 packages, roughly 20 seconds. `--omit=dev` skips Vite and the Electron builder, because the frontend is already built.

### 4. Write the start script

Save as `C:\GenStudioServer\start-server.cmd`:

```bat
@echo off
cd /d "%~dp0"
set GENSTUDIO_MODE=server
set PORT=3001
set GENSTUDIO_JWT_SECRET=<the 64 hex characters>
set GENSTUDIO_ADMIN_LOGIN=admin
set GENSTUDIO_ADMIN_PASSWORD=<at least 8 characters>
set TRUST_PROXY_HEADERS=0
node server.js
```

> **The working directory is load-bearing.**
> `cd /d "%~dp0"` is not boilerplate. The database and every asset live in `<working directory>\data`, so starting from somewhere else creates a second, empty database and the server looks like it lost everything.

### 5. Test it in the foreground

Run the script from a console. You are looking for the seeding line and the port banner:

```
👤 Seeded initial administrator "admin" from the environment
🚀 3D Gen Studio Backend running at http://localhost:3001
📁 Local Workspace: C:\GenStudioServer\data
🖥️  Serving bundled UI from dist/
```

Check it, then stop with `Ctrl+C`:

```sh
curl http://localhost:3001/api/health
```

### 6. Install it as a service

**NSSM** is the least surprising option: it restarts the process if it dies and captures output to a file, neither of which Task Scheduler does well.

```bat
nssm install GenStudioServer "C:\Program Files\nodejs\node.exe"
nssm set GenStudioServer AppDirectory "C:\GenStudioServer"
nssm set GenStudioServer AppParameters "server.js"
nssm set GenStudioServer AppEnvironmentExtra ^
  GENSTUDIO_MODE=server ^
  PORT=3001 ^
  GENSTUDIO_JWT_SECRET=<secret> ^
  GENSTUDIO_ADMIN_LOGIN=admin ^
  GENSTUDIO_ADMIN_PASSWORD=<password> ^
  TRUST_PROXY_HEADERS=0
nssm set GenStudioServer AppStdout "C:\GenStudioServer\logs\out.log"
nssm set GenStudioServer AppStderr "C:\GenStudioServer\logs\err.log"
nssm start GenStudioServer
```

`AppDirectory` is the same working-directory rule as the batch file — it is what decides where `data\` ends up.

Without NSSM: Task Scheduler, a task triggered *At startup*, **Run whether user is logged on or not**, action = `start-server.cmd`. Whichever account runs it needs write access to `C:\GenStudioServer`.

### 7. Open the firewall

```powershell
New-NetFirewallRule -DisplayName "3D Gen Studio Server" `
  -Direction Inbound -Protocol TCP -LocalPort 3001 -Action Allow
```

For HTTPS, put IIS with Application Request Routing (or any proxy you already run) in front, and set `PUBLIC_BASE_URL` to the public address — same as the Synology guide, step 7.

## Once it is running

### Replace the seeded administrator

Sign in with the seeded account, then **Settings → Server** to create your own administrator, and *disable* the seeded `admin`. Create the new one first: the server refuses to disable or demote the last enabled administrator.

The user manager creates accounts, changes roles and enables or disables people, but it **cannot change an existing password**. The API can — `PATCH /api/users/:id` with `{"password":"…"}` as an administrator — so use that if you would rather keep the `admin` account.

### Roles

| Role | Can do |
| --- | --- |
| **Administrator** | Everything, plus user management. |
| **User** | Read and write projects, assets and workflows. |
| **Viewer** | Read only. Writes are refused with *"Your role is read-only"*. |

The server enforces roles regardless of what the interface offers, and the banner under the header explains why an action is unavailable.

### Connect the desktop apps

On each user's machine: **Settings → Server**, enter the address `http://host:3001` and their login. From then on, projects and assets come from the server while ComfyUI, the mesh and motion tools and their API keys stay local.

The password never reaches the browser. It is posted to that user's own backend, which signs in on their behalf and holds the session token itself.

### Browse from a web browser

The server also serves the interface, so anyone can open `http://host:3001` and sign in to browse projects and assets without installing anything. Generation is unavailable there — ComfyUI and the mesh tools need the desktop app — but everything already produced is visible.

### Backups

Back up `data/`, and **stop the server first**. `app.db` is SQLite in WAL mode, so a copy taken while the server is writing can be torn. Stopping the container or service for the few seconds a copy takes avoids the question. If you must copy it live, take `app.db`, `app.db-wal` and `app.db-shm` together — a database file without its WAL is missing recent writes.

### Updating

Rebuild and reload the image, or copy the changed files and restart the service.

One thing to remember: `storage.js`, `serverMode.js` and `auth.js` run on **both** sides. Change any of those and you must update the server **and** rebuild the desktop app, or the fix will appear not to work.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Exits immediately, log mentions `GENSTUDIO_JWT_SECRET` | The secret is shorter than 16 characters, missing — or, on DSM, blanked by a `${…}` substitution that found no `.env` | Check what actually reached the container: `docker inspect <name> --format '{{range .Config.Env}}{{println .}}{{end}}'`. An empty value means it never arrived — inline the values (Synology, step 5). Otherwise generate a longer secret. |
| Fixed a variable, same error after restarting | The container was restarted, not recreated, so it kept its original environment | Container Manager: **Project → Action → Build**. CLI: `docker compose up -d`, which recreates. |
| A `.env` file is ignored on the NAS | It is really `.env.txt` — File Station and Notepad append the extension and DSM hides it | `ls -la` in the project folder. Inline values avoid the question entirely. |
| *"Could not create the initial administrator"*, then exits | Administrator password shorter than 8 characters | Lengthen it. |
| *"Invalid credentials"* with a password you know is right | The account was never created, from an earlier failed seed | Read the startup log for the seeding line. The seed only runs while the user table is empty. |
| Container restart loop, `SQLITE_CANTOPEN` | The bind-mounted data folder is not writable by uid 1000 | `chown -R 1000:1000` on the folder — Synology, step 4. |
| `exec format error` when the container starts | Image built for the wrong CPU architecture | Rebuild with `--platform linux/arm64`, or check `uname -m` again. |
| Browser shows a blank page | Stale or missing `dist/` in the deployed copy | Run `npm run build` and redeploy. |
| Interface loads but images and thumbnails are broken | Asset URLs are minted with the wrong host or port | Set `PUBLIC_BASE_URL`. The first request logs the host it resolved — that log line tells you what the server thinks it is. |
| Desktop app suddenly shows no projects | Its session was rejected, so data routes are blocked | **Settings → Server**, sign in again. It blocks rather than falling back to the local database, because showing a different empty workspace reads as data loss. |
| Other people's changes appear late | A reverse proxy is buffering the `/api/events` stream | Disable response buffering for that path, or reach the server directly. |
